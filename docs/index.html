OpenMind · project page

One learner, one journey, one decision.

OpenMind is an open-source STEM learning platform. Every answer a learner gives becomes authoritative evidence; the learner model is a projection of that record; and every surface that recommends work reads the same decision, so one learner and one record always yield one next step. Maths, physics, chemistry, biology and computer science, across 26 qualifications in 20 countries, in 15 languages — and it runs offline.

This page is static; the application is not. GitHub Pages serves files, and OpenMind is a stateful server application: its API routes grade answers, its session cookies identify a learner, and its store is a directory of JSON files on a real disk. A static export would ship pages whose data never loads.

So the app is not hosted here. It is deployed in one command, on hardware you control — the design goal is a school server, a laptop, or a phone hotspot with no internet.

Run it

git clone https://github.com/DaMaker1291/Non-profit.git
cd Non-profit
npm install
./start-openmind.sh        # → http://localhost:3000

Or with Docker, which is the supported deployment path:

docker compose up -d       # → http://localhost:4173
# learning data persists in ./openmind-data on the host

Copying that one directory backs up, moves or duplicates an entire deployment — profiles, evidence ledgers, classes, rooms and packs. There is no external database to migrate, and no learner data in this repository.

Hosting it for real

Any host that runs a container with a persistent disk works. Because the store is a directory of files, a host whose filesystem is wiped between requests would lose learner records — that is the one requirement worth checking before you pick one.

HostFit
A school server, VPS or Raspberry PiThe design target: data never leaves the building.
Render / Railway / Fly.io with a mounted volumeOne container plus a disk. Point OPENMIND_DATA_DIR at the mount.
Static hosts (GitHub Pages, Netlify, S3)Cannot run the API routes or hold the store. This page is what they can serve.

What is real in it

  • Evidence, not estimates. Every claim about a learner is folded from recorded answers. A dimension nobody measured reads “not yet measured”, never 0%.
  • One curriculum, chosen per subject. GCSE Maths (Foundation) beside A-Level Physics is an ordinary year; each subject resolves to its own qualification, tier and practice depth.
  • One decision door. Home, the offline pack, the API and the tutor all read the same decision over the same ledger — a surface that skips the ledger makes a different decision, not a smaller one.
  • Documents nothing it cannot — this page is the honest version of “hosted”: run it where it actually works.

Verification

The repository guards itself with five gates, run in CI on every push:

npm run typecheck       # the compiler
npm run verify          # the engine suite, one runner, one compile mirror
npm run content-check   # the content graph: concepts, misconceptions, item identity
npm run verify:q        # the question audit, 300 draws per generator
npm run e2e             # the HTTP suite against a running server

Contribute

The curriculum is plain data and the store is a directory of JSON files. Fork it, translate lib/i18n.ts, extend lib/genome.ts, deploy it on a school server, and send improvements back by pull request. The non-English dictionaries are machine-drafted and the highest-value contribution available is native-speaker review.
